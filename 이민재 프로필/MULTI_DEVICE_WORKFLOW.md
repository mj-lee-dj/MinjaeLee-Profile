# 여러 컴퓨터에서 작업하는 Git 운영 기준

이 프로젝트는 GitHub를 컴퓨터 간 작업 상태의 기준으로 사용한다. Google Drive는 원본 사진과 문서 보관에 사용하고, 각 컴퓨터에는 서로 독립된 로컬 Git clone을 둔다.

## 핵심 원칙

- `origin/main`: 운영 사이트에 배포된 기준선
- `codex/<작업명>`: 아직 운영 배포하지 않은 작업 브랜치
- 한 번에 한 컴퓨터에서만 작업한다.
- 다른 컴퓨터로 옮기기 전에는 진행 중인 브랜치를 commit하고 GitHub에 push한다.
- `main` push는 Vercel Production 배포이므로 사용자의 배포 승인 없이 수행하지 않는다.
- 운영 관리자 페이지의 `운영 사이트 저장 및 배포`도 `main`을 변경하므로 사용 후에는 다음 코드 작업 전에 반드시 fetch한다.

## 언제 GitHub를 확인하는가

매 프롬프트마다 확인하지 않는다. 아래 중 하나일 때만 **새 작업 세션**으로 판단한다.

1. 새 Codex 작업에서 처음으로 파일을 수정하려는 때
2. Codex 앱이나 컴퓨터를 다시 시작한 뒤 처음으로 파일을 수정하려는 때
3. 집 컴퓨터·노트북·학교 컴퓨터 등 기기를 바꾼 때
4. 다른 기기에서 commit/push했거나 관리자 페이지로 저장·배포했다고 사용자가 말한 때
5. 이전에 다른 기기에서 작업하던 브랜치를 이어받는 때
6. commit·push·배포 직전

다음은 새 작업 세션으로 보지 않는다.

- 같은 Codex 작업에서 연속으로 이어지는 수정 요청
- 같은 컴퓨터·같은 작업 브랜치에서 중단 없이 진행하는 후속 프롬프트
- 날짜만 자정을 넘어 바뀐 경우
- 코드나 파일을 바꾸지 않는 질문·설명·기획 요청

날짜가 바뀌었더라도 앱과 작업을 계속 열어 둔 상태라면 재확인이 필요 없다. 반대로 같은 날이라도 기기를 바꾸거나 앱을 다시 열어 파일 작업을 시작하면 한 번 확인한다.

## 세션 시작 확인

에이전트가 첫 파일 변경 전에 다음을 확인한다.

```bash
git fetch origin --prune
git status --short
git branch --show-current
git rev-list --left-right --count HEAD...origin/main
```

- 작업 트리가 깨끗하고 새 작업을 시작한다면 최신 `main`에서 새 `codex/<작업명>` 브랜치를 만든다.
- 작업 트리가 더러우면 pull, switch, merge를 자동으로 하지 않는다. 기존 변경의 소유와 목적부터 확인한다.
- 현재 브랜치가 원격보다 뒤처졌다면 파일을 수정하기 전에 변경 내용을 읽고 안전한 합류 방법을 정한다.

## 다른 컴퓨터로 작업을 넘길 때

1. 변경한 정확한 파일만 검토한다.
2. 작업 단위로 commit한다.
3. `codex/<작업명>` 브랜치를 GitHub에 push한다.
4. `HANDOFF.md`에 현재 브랜치, 마지막 커밋, 다음 작업을 기록한다.

작업 브랜치 push는 운영 배포가 아니다. 다른 컴퓨터에서는 독립된 로컬 clone에서 fetch한 뒤 같은 원격 브랜치를 이어받는다.

## 운영 배포할 때

1. 테스트와 브라우저 검증을 완료한다.
2. `git fetch origin --prune`으로 `origin/main`의 최신 상태를 다시 확인한다.
3. 충돌과 관리자 페이지의 최근 저장 여부를 확인한다.
4. 사용자가 배포를 승인한 경우에만 `main`에 반영하고 push한다.
5. Vercel Production Ready와 실제 운영 화면을 확인한다.

## 충돌 및 보안 방지

- Google Drive가 동기화한 동일한 `.git` 폴더를 여러 컴퓨터에서 직접 공유하지 않는다.
- 관리자 페이지 저장 후 열려 있던 코드 작업은 반드시 원격 변경을 다시 확인한다.
- `git reset --hard`, force push, 무조건적인 stash/pop으로 충돌을 덮지 않는다.
- 비밀값, 원본 대용량 사진, 영상, 임시 스크린샷은 commit하지 않는다.
- 충돌이 발생하면 어느 기기의 내용이 최신인지 추측하지 말고 양쪽 diff와 `HANDOFF.md`를 확인한다.
